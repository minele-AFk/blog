## PHP 漏洞的适用性

项目是 Next.js / React / Node.js 应用，部署配置使用 OpenNext + Cloudflare Workers。仓库未发现 PHP 文件、Composer 配置或 PHP 服务启动配置，本项目没有直接使用 PHP 的执行路径。

[PHP 官方 10 月 21 日公告](https://www.php.net/archive/2026.php#2026-10-21-5) 涉及 CVE-2026-109618、CVE-2026-109619，修复版本为 PHP 8.2.35、8.3.36、8.4.27、8.5.12。[10 月 23 日补充公告](https://www.php.net/archive/2026.php#2026-10-23-1) 提到特殊 session 配置下的后续风险，建议在适用环境关闭 `session.upload_progress.enabled`，等待相应更新。

上述 PHP 漏洞不直接影响本仓库描述的博客架构。其他主机、同服务器上的独立 PHP 服务及托管平台内部组件不在此次本地代码检查的证明范围内。

## 发现与修复

| 项目 | 发现 | 本地修复 |
| --- | --- | --- |
| 依赖 | 初始 `npm audit` 报告 11 个受影响包：2 critical、7 high、2 moderate | 更新锁文件和安全版本下限；最终审计为 0 |
| 定时同步身份绕过 | `User-Agent: Cloudflare...` 可以直接获得同步权限 | 删除该分支；只接受配置的强随机 Bearer secret，拒绝 GET 和查询参数 token |
| SVG 存储型脚本风险 | 上传允许 SVG，文本开头校验无法删除脚本；同源打开文件可能执行活动内容 | 禁止新 SVG 上传；上传路由和静态资产增加 sandbox CSP / nosniff，约束旧 SVG |
| 登录暴力尝试 | 无条件信任客户端 `X-Forwarded-For`；限流 Map 的部分条目永不清理 | Workers 使用边缘 IP 和 RateLimit binding；Node 默认共同桶，受信代理可显式配置；限制 5 次/15 分钟并清理过期记录、限制 Map 大小 |
| Markdown 可执行前言 | gray-matter 自带 `---js` / `---javascript` eval 引擎，默认解析和字符串序列化可能进入该路径 | 读取前限定 YAML；写入传递内容对象，避免把正文当成可执行前言；构建生成器采用同样规则 |
| Bangumi 凭证信任边界 | 带访问令牌的请求发往 `api.bgmapi.com` 镜像域名 | 改用官方 `api.bgm.tv`，拒绝重定向；详情 ID 仅允许数字 |
| 图片代理 | 默认跟随重定向；响应全部读入内存；缓存键支持任意查询参数，旧缓存永久保留 | URL 域名/协议/路径检查、拒绝重定向、10 秒超时、2 MiB 流式上限、图像类型与魔数检查；规范 URL、SHA-256 键、KV 7 天 TTL、本地缓存淘汰 |
| 管理端输入 | 多个写接口直接解构不受控 JSON，未限制大小、字段类型、URL 协议，允许透传更新字段 | JSON 流式上限 256 KiB（登录 4 KiB）；拒绝 null/数组/非法 JSON；字段白名单、文本/数组/计数/URL 校验；禁止改写记录 ID |
| 上传资源消耗 | 在检查单文件大小前已解析完整 multipart；R2 未执行容量检查 | 流式限制 multipart 总大小约 10 MiB + 64 KiB；本地与 R2 都检查文件数/总容量；随机 UUID 文件名 |
| 音乐接口 | 主通道校验 ID，但失败回退通道仍可能拼入未校验的参数 | 入口统一校验来源、全部 ID 和数量，拒绝非法输入，去重后再访问上游 |
| JWT / 密码 | 验签后未检查管理员身份和必需过期时间；同步 bcrypt 占用事件循环 | 限定管理员身份、有效期和 HS256；异步 bcrypt；初始化拒绝示例/过短/超过 72 UTF-8 字节的密码；强化生产密钥占位符检查 |
| 响应与交付 | 缺少统一防嵌入、MIME、上传隔离头；CI 不运行安全回归 | 添加安全响应头、后台 API no-store、禁用框架标识；部署前运行测试、类型检查、依赖审计；checkout 不保留凭证 |

依赖公告中的攻击条件不同，受影响包数量不等同于实际可利用漏洞数量。例如项目已禁用 Next 图片优化，也未使用 `use cache`，但仍升级框架以消除对应版本风险。

## 范围与限制

审查包括依赖、全部 API 路由、认证、上传读取、Markdown、外部请求、相关存储适配和部署工作流；保留已有 Markdown HTML 净化。未登录 Cloudflare/GitHub 管理后台，未对线上站点发送攻击载荷，未进行浏览器视觉验收、主机入侵排查或供应商内部组件审计。

Cloudflare RateLimit 按边缘位置生效，不能当成全球严格计数器；15 分钟桶属于单进程补充措施。参见 [Cloudflare 官方限流文档](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)。公开查询接口仍需结合平台流量配额/WAF 应对分布式流量攻击。管理员令牌仍按既有设计存于 localStorage，本次上传隔离及 HTML 净化不能替代对未来 XSS 的持续防护。
